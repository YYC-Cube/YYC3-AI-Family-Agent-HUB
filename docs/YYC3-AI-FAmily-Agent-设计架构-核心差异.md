一、两套体系的核心差异

同一套 8 位家人名称,完全不同的定位轴:

 对比维度              │ 编程体系 ( YYC3-AI-FAmily-Agent-编程体系 ) │ 企业蓝图 ( YYC3-FAmily-AI-Agent-企业蓝图 )
───────────────────────┼────────────────────────────────────────────┼───────────────────────────────────────────────────
 映射轴                │ 技术栈层 (LSP/MCP/Skills/代码)             │ 五维价值矩阵 (经管运维营/人资进销存/...)
 输出目标              │ 软件制品 (代码/测试/文档)                  │ 企业运营 (决策/流程/效率)
 天枢                  │ 代码编排 · 分布式监控 · 智能调度           │ 五步决策法 · 战略权重矩阵 · 任务分解
 千行                  │ NLU 意图识别 · Prompt Engineering          │ 需求理解/流程路由/客户接入/故障接报/营销入口
 万物                  │ 数据洞察 · 知识图谱                        │ 经营分析/流程优化/运营分析/诊断分析/市场分析
 先知                  │ ARIMA/Prophet/LSTM 时序                    │ 趋势预测/风险预警/需求预测/容量预测/效果预测
 伯乐                  │ 协同过滤 · 用户画像                        │ 商机/人才/客户/工具/投放推荐
 守护                  │ UEBA · SOAR · 代码安全                     │ 合规审计/权限控制/数据安全/安全防护/投放安全
 宗师                  │ SAST · 性能剖析 · LLM 代码理解             │ 标准制定/质量管控/质量监控/性能优化/效果优化
 灵韵                  │ 生成式 AI · 多模态                         │ 战略构想/方案设计/内容运营/文档生成/创意生成
 模型绑定              │ 未明确                                     │ 明确 (天枢→Qwen3.6-27B+LoRA, 守护→+security LoRA)
 文件类型              │ 纯文档/规范 (无代码)                       │ 文档 + 可运行 Python 代码 + Docker 部署
 MBTI                  │ 无 (用推理类型+情感铭刻)                   │ 有 (ENTJ/INTP/INTJ/ENFP 等)

## 三、对我们 OpenClaw 沙箱 Agent 配置的启示

我们当前创建的 3 个 Agent ( main / research / coder ) 对应的是编程体系维度的简化版。如果要真正落地企业蓝图,需要:

1. 提示词引擎: 部署  13-v3/1300/prompt-engine/prompt_engine.py  中的 CO-STAR+CRAFT 双框架
2. 8 Agent 完整版: 当前只有 3 个,蓝图定义了 8 个独立 Agent(含五维职能映射)
3. 模型绑定: 蓝图指定了每个 Agent 的专用 LoRA 适配器(如天枢→mgmt-v2,守护→security-v1)
