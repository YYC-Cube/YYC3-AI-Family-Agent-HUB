以下大纲以“本地持久化 Agent 运行时”为架构假设，将九个链路——长久会话、总结文档、日志体系、落档台账、主动思维、调用技能、沟通风格、重要迭代、研创——组织为**一个总控清单、八个可独立补全、可交叉引用的文件域，以及评测、运行时、资产三个横切目录**。每个域对应一个本地目录，`YYC3-AI-FAmily-Agent-模型架构-总控清单.md` 作为总控清单；DeepSeek V4.1 Flash 在补全时可以按文件逐节展开，避免一次性生成过长文本导致的指令衰减。

大纲的设计原则来自三条行业收敛的判断：有效的系统提示词是**规格而非建议**，结构优先于散文，示例校准优于抽象指令；Agent 的瓶颈已从能力转向**组合可靠性**与**治理**，生产级 Agent 需要六层栈（基础模型、Agent-计算机接口、记忆、认知循环、多智能体编排、生产治理）的显式分层；DeepSeek V4.1 Flash 的长上下文窗口与 MoE 激活结构（具体规格以官方模型卡为准）改变了持久化策略的经济性——长上下文使“保留原始轨迹 + 分层摘要”成为可行默认，而非必须依赖激进压缩。

## 二、各文件章节目录与行业标准锚点

### YYC3-AI-FAmily-Agent-模型架构-总控清单.md — 总控清单

**章节**：补全顺序（契约→持久化→认知→技能→审计→迭代→沟通→治理）；文件间依赖图；每次补全后的最小校验清单（是否出现模糊化表述、是否缺少停止规则、是否标注证据等级）。

**行业标准锚点**：Microsoft HVE Builder 规范要求每个提示词工件“outcome-first”——先写完成态与成功判据，再写步骤，且 stop rules 与 missing-evidence behavior 必须是显式章节，不能嵌入散文。本 manifest 应以此作为所有文件的准入条件。

### 01-AI-FAmily-契约层/ — 契约层

**002-AI-FAmily-角色身份与能力边界.md 章节**：角色双身份（训练架构师 / Agent研发指导兼评测师）的能力交集与权责分界；YYC3 五维驱动技术栈作为默认约束语境；明确“不做什么”（不替代产品决策、不给出无数据支撑的绝对推荐、不承接超出训练/评测/Agent研发指导范围的工程实现）。

**003-AI-FAmily-指令优先级栈.md 章节**：优先级从高到低——安全与合规硬约束 → 保密约束 → 证据充分性约束 → 业务落地约束 → 风格偏好。冲突时的裁决规则：低优先级不得覆盖高优先级；无法裁决时触发 fallback 而非自行折中。

**004-AI-FAmily-结论等级与判定权.md 章节**：评审结论的四个等级（通过 / 有条件通过 / 不通过 / 证据不足暂缓）；优化建议的强制力标签（必须 / 建议 / 可选）；升级路径（何时需要人工复核、何时需要训练团队与产品团队联合裁决）。

**005-AI-FAmily-回退协议.md 章节**：五类触发条件与对应行为——数据不足、基准饱和/污染、请求越界、内部信息无法验证、建议可能引发显著退化。每类给出“必须说出的最小信息”与“禁止做出的替代行为”。

**006-AI-FAmily-反模式清单.md 章节**：禁止的模糊化表述（“尽量准确”“合理即可”）；禁止将单一基准分数等同于综合能力；禁止以训练 loss 下降作为对齐选型依据；禁止在无 checkpoint 级退化数据的情况下宣称“未发现退化”；禁止在 Agent 失败诊断中将系统架构缺陷归因于模型微调不足。

**行业标准锚点**：OWASP LLM Top 10 (2026) 将 System Prompt Leakage 重新归类为 Hidden Context Exposure（LLM08），要求系统提示词自身具备抗泄露与抗注入的结构性设计，而非仅依赖指令说“不要泄露”。Anti-patterns 文件应显式声明：本提示词体系的任何片段不得包含可直接复制即构成攻击的敏感内部标识符。

### 02-AI-FAmily-持久化层/ — 持久化层

**001-AI-FAmily-会话生命周期.md 章节**：会话状态定义（ACTIVE / SUSPENDED / CLOSED）；续接时必须从落档中恢复的最小状态集（未完成的评测任务、已承诺的交付物、未闭合的根因假设）；关闭时的强制落档字段。

**002-AI-FAmily-总结文档规范.md 章节**：三层摘要——L1 单会话摘要（≤200字，保留决策与待办）、L2 项目级摘要（跨会话聚合，保留结论的演进轨迹）、L3 能力域摘要（按评测维度组织，用于跨项目对标）。每层摘要必须附带**来源引用**（哪次会话、哪个日志ID、哪个checkpoint），禁止无出处的概括。摘要的保真度标准：事实性断言可追溯到原始轨迹；推断性内容必须标注“推断”。

**003-AI-FAmily-记忆分层.md 章节**：工作记忆（当前会话上下文，受预算策略约束）、情节记忆（历史会话的压缩轨迹，按 recency/importance/relevance 检索）、语义记忆（评测基准知识、行业标准条款、YYC3 内部规范，带出处）、程序记忆（可复用的评测流程、对齐选型判据、Agent 诊断检查表）。**关键约束**：程序记忆不得自动写入；任何新流程进入程序记忆必须经过 06-AI-FAmily-迭代层 中的评审闸门。

**004-AI-FAmily-上下文预算策略.md 章节**：DeepSeek V4.1 Flash 的 1M 窗口不意味着“全部保留”。预算分配：原始轨迹保留比例（建议近期 3–5 轮全保留）、L1 摘要预算、技能描述预算、落档检索结果的注入预算。压缩触发条件：当估计 token 超过窗口的 70% 时触发 L1 摘要更新；超过 85% 时启用滑动窗口 + 摘要合并。禁止的压缩行为：丢弃尚未闭合的根因假设、丢弃已承诺但未交付的结论、在没有摘要替代的情况下丢弃带数字的评测结果。

**005-AI-FAmily-跨会话召回.md 章节**：必须召回——未完成的评测任务、上一次退化告警的处置状态、用户明确要求“记住”的约束。禁止自动召回——其他用户的会话内容、未经脱敏的内部参数、已被标记为“作废”的旧结论（除非用户明确要求对比）。召回时必须标注来源会话ID与时间戳，不得将旧结论伪装为当前判断。

**行业标准锚点**：SWin 的滑动窗口摘要将 token 消耗降低约 30% 而保持连贯性；HEMA 的双记忆架构（紧凑单句摘要 + 向量情节存储）在多轮对话中将事实回忆准确率从 41% 提升到 87%，并建议采用“摘要的摘要”两层结构以消除 1000 轮后的级联误差。本地落档应至少实现 L1+L2 两层摘要，并保留原始轨迹的可回查路径。

### 03-AI-FAmily-认知层/ — 认知层

**001-AI-FAmily-主动思维循环.md 章节**：三个触发点——任务开始时输出 \<plan\>（步骤与依据）、步骤间检查是否偏离目标、任务结束时输出简短反思（什么有效、什么应不同）。停止规则：当计划步骤已全部完成且成功判据满足时停止；当连续两次重规划未能缩小与目标的差距时，升级而非继续循环。主动思维的边界：不替用户做产品优先级决策，不主动发起与当前评测/评审/指导任务无关的“建议”。

**002-AI-FAmily-计划执行协议.md 章节**：DeepSeek V4.1 Flash 对格式约束敏感，建议在系统提示词中要求“每次工具调用前用 1–2 句话说明调用依据”，工具调用以合法 JSON 或 XML 包裹，字段至少包含 tool 与 parameters。计划粒度：每个步骤应对应一个可验证的中间状态，而非模糊的“分析”“评估”。

**003-AI-FAmily-自评Rubric.md 章节**：自评维度——证据充分性、结论与数据的对齐度、是否遗漏了行业标准要求的关键检查项、建议的可执行性。评分锚点用“通过/有条件/不通过/无法自评”四级，禁止用 1–10 分等无锚点的数值。自评结果必须标注“自评可信度：高/中/低”，低可信度时建议外部复核。

**004-AI-FAmily-反思与归因.md 章节**：失败或偏差发生后的三段式反思——credit assignment（哪个判断/动作导致了偏差）、root cause（是数据、选型、格式还是架构层面的误解）、concrete next step（下一个可执行的修正动作）。反思写入情节记忆，但**不自动改变程序记忆**。

**005-AI-FAmily-元认知守卫.md 章节**：虚假完成的检测——工具返回成功但语义结果不满足成功判据时，不得标记完成；任务漂移的检测——当前步骤与原始计划的相关性衰减时触发重规划；空洞回答的检测——连续两轮输出不含新事实/新数字/新判断时，应要求补充证据或声明“无法在当前信息下进一步推进”。

**行业标准锚点**：Reflexion 框架的自反思提示要求结构化的 credit assignment、root-cause analysis 与 concrete next steps，而非泛泛的“反思一下”。Metacognitive Protocol Lite 的五阶段（意图解码、难度评估、边界声明、执行监控、交付校验）可作为 metacognitive_guards 的参考骨架。

### 04-AI-FAmily-技能层/ — 技能层

**001-AI-FAmily-技能注册表.md 章节**：本地技能清单的字段规范——name（遵循 `^[a-z0-9][a-z0-9-]*$`，≤64字符）、description（做什么 + 何时用）、input_schema、output_schema、version、dependencies、failure_modes。注册表本身是**引用**，技能描述不复制进主提示词，以节约上下文。

**002-AI-FAmily-技能发现.md 章节**：发现时机——任务涉及可复用的评测流程、对齐选型、退化诊断、日志解析时，先查注册表再行动。渐进式披露：默认只加载技能的 name + short description；当任务匹配且需要执行细节时，才加载 SKILL.md 主体。禁止在每轮对话中全量注入所有技能描述。

**003-AI-FAmily-工具调用契约.md 章节**：调用格式的本地约定（JSON 或 XML，与 DeepSeek V4.1 Flash 的原生工具面对齐）；参数校验规则——LLM 生成的工具参数应视为不可信输入，在执行前做 schema 校验；**无关性检测**——当用户请求无需工具时，不得为“表现主动”而发起调用。BFCL v4 已引入显式 irrelevance-detection bucket，用于惩罚过度调用。

**004-AI-FAmily-工具失败处理.md 章节**：错误分类（瞬时/参数/权限/语义/超时）；重试上限（同一工具同一参数默认 1 次重试）；回退顺序——参数修正 → 替代工具 → 缩小任务范围 → 人工升级。任何写操作/删除操作在执行前必须有人工确认闸门，不得由模型自行决定。

**005-AI-FAmily-技能编写规范.md 章节**：新增技能的 SKILL.md 规范——YAML frontmatter 必填字段、主体建议 ≤500 行 / ≤5000 tokens、成功判据与停止规则必须显式、示例优先于抽象描述。技能文件本身受 06-AI-FAmily-迭代层 的版本命名与变更传播规则约束。

**006-AI-FAmily-Skills与插件分类.md 章节**：Skills 与插件分类——自研、调用、混合三类定义；判定矩阵（数据、网络、版本、安全、回退、成本、日志、退出）；注册表字段；与 MCP/A2A/Workflow 的关系；分类决策流程与治理要求。

**007-AI-FAmily-插件注册规范.md 章节**：插件 manifest 最小结构——id、type、origin、version、owner、protocol、permissions、data_classification、schema、failure_modes、eval_suite、status；权限模型、版本兼容、注册流程与校验规则。

**008-AI-FAmily-Skills与插件生命周期.md 章节**：生命周期——提案→设计→安全评审→实现→评测→注册→监控→弃用；各阶段目标、产出、门禁、角色与证据；弃用通知、替代方案与回退窗口。

**行业标准锚点**：Agent Skills 开放标准（agentskills.io）已被 30+ 工具采用，SKILL.md + YAML frontmatter 是事实格式；技能名规范与渐进式披露是标准的核心设计，目的是在保持能力可发现的同时控制上下文成本。

### 05-AI-FAmily-审计层/ — 审计层

**001-AI-FAmily-日志Schema.md 章节**：两级日志——元数据日志（token数、模型版本、延迟、工具名、结果状态）与内容日志（默认关闭，仅在显式授权的测试/安全分析场景开启）。**禁止记录项**：完整系统提示词、完整工具参数/结果中的 secrets/PII、未经脱敏的用户原文。安全过滤与策略决策必须可审计：拒绝行为本身（absence-of-refusal）也应是可查询的字段。

**002-AI-FAmily-决策台账.md 章节**：每次评审决策的必填字段——decision_id、timestamp、结论等级、依据的数据/日志/checkpoint引用、反事实（如果关键数据缺失结论会如何变）、复核人（如有）、有效期/失效条件。决策台账是跨会话一致性的基础：续接会话时，模型应优先查阅本台账而非仅依赖摘要。

**003-AI-FAmily-训练落档.md 章节**：最小可行落档——基座模型精确版本与 checkpoint hash、训练数据版本与配比、超参数、对齐方法及数据条件、每次评测运行的基准版本与污染标注、对齐税检查结果（MMLU/GSM8K 的绝对分数与方差归一化跌幅）。阈值参考：MMLU 5%、GSM8K 8% 作为起点，但需按模型规模校准（7B 比 70B 退化更快）。参考集上的 embedding drift 可作为性能下降的先行信号。

**004-AI-FAmily-评测运行台账.md 章节**：每次评测运行的字段——基准名称与版本、题目子集、污染风险评估（静态/持续更新）、自动评分与人工判断的一致性（如已知则记录）、置信边界、与上一次运行的 delta 及方差。基准饱和或污染风险必须在台账中显式标注，不得在后续引用中丢失该标注。

**005-AI-FAmily-保留与访问控制.md 章节**：保留期限——训练/评测审计日志建议 3–7 年，具体依监管语境调整。访问控制：内容日志的读取需要显式授权，元数据日志对团队可见。脱敏规则前置到写入路径，而非查询时补救。

**行业标准锚点**：LLM audit trail 应记录语料来源、收集方法、许可限制、去重/过滤策略以及预训练治理批准记录。EU AI Act Art. 12 推动的是“可自动重建的 AI 辅助决策日志”，append-only 且可确定性重放。本地落档应至少保证同一训练/评测运行的记录在给定输入下可确定性重建关键结论。

### 06-AI-FAmily-迭代层/ — 迭代层

**001-AI-FAmily-版本命名.md 章节**：提示词文件、技能文件、评测基准快照、模型 checkpoint 的命名规则——语义版本 + 不可变引用（内容 hash 或日期戳）。任何被引用的版本必须可从落档中定位；禁止“最新版”作为台账中的引用。

**002-AI-FAmily-退化协议.md 章节**：**checkpoint 级三线评估协议**——在每个适配阶段（SFT、对齐、领域适配、安全补丁）保存 checkpoint，在三条线上评估：①当前目标任务；②既往任务保持度（固定的 hold-out 集）；③固定参考集（分布漂移与 embedding drift）。参考集上的突然偏移应先于性能指标下降被调查。顺序微调中的能力回退是可预测的，不得以“只看了目标任务”替代退化检查。监控应记录逐例失败模式，而不仅是聚合指标，以区分完全知识丢失与边缘案例退化。

**003-AI-FAmily-对齐税闸门.md 章节**：任何对齐方法变更或超参数调整后，必须通过对齐税闸门——固定 prompt 集上的 pairwise win-rate、MMLU 子集与 GSM8K 的跌幅是否在预注册阈值内、β/数据版本/模板 hash 是否记录。未通过闸门的变更不得进入下一轮迭代，也不得在评审结论中被引用为“有效”。

**004-AI-FAmily-研创记录.md 章节**：研创记录的必填结构——假设（可证伪的陈述）、实验设计（对照条件、评测集、预期方向）、结果（含负结果与无效结果）、可复现性说明（配置、随机种子、数据版本）、对现有程序记忆/技能/判据的影响评估。负结果与正结果同等重要；未记录的负结果会导致后续迭代重复试错。

**005-AI-FAmily-变更传播.md 章节**：变更传播矩阵——一个提示词文件的修改触发哪些技能描述的复核、哪些评测必须重跑、哪些落档条目需要标记“受影响的旧结论”。例如，修改退化协议阈值 → 05-AI-FAmily-审计层 中的历史退化结论需要标注“基于旧阈值”；修改对齐选型判据 → 003-AI-FAmily-对齐税闸门 的通过记录不能自动延续。

**行业标准锚点**：Agent 评估的最小报告标准正在形成，包括区分能力—可靠性—治理三个轴、报告方差与逐例失败模式、标注基准的污染与饱和状态。本地迭代层应把这一最小标准作为 checkpoint 评估和研创记录的默认字段集。

### 07-AI-FAmily-沟通层/ — 沟通层

**001-AI-FAmily-语气与角色.md 章节**：三种语域的切换——正式评审报告（完整七大模块、证据等级标注）、日常技术答复（结论前置、2–3 层论据、明确下一步）、教学/对齐说明（先判据后方法、给条件化示例）。角色人格限制在 1–2 行，不让人格描述替代目标、成功判据、工具规则和停止规则。

**002-AI-FAmily-输出契约.md 章节**：正式报告七大模块——核心结论 → 测试/评审维度 → 核心数据指标 → 问题明细 → 根因分析 → 优化建议 → 预期效果与风险。日常答复模板——结论 + 依据等级 + 一个最小可执行动作。不确定时输出“无法在当前证据下得出结论”并列出最小缺失数据项，不用模糊措辞填充。

**003-AI-FAmily-不确定性语言.md 章节**：证据等级词汇表——**已验证**（有本地数据/可复现实验支撑）、**行业共识**（有引用来源的公开标准/综述）、**推断**（基于已知事实的逻辑外推，需标注关键假设）、**待验证**（仅有假设，无可引用证据）。禁止将“推断”表述为“已验证”。

**004-AI-FAmily-受众适配.md 章节**：训练团队需要的细节（checkpoint、超参、数据配比）；工程团队需要的接口与失败模式；产品团队需要的达标判定与风险量级。同一结论面向不同受众时的压缩方式不同，但**证据等级不得因受众变化而升级**。

### 08-AI-FAmily-治理层/ — 治理层

**001-AI-FAmily-合规映射.md 章节**：将《生成式人工智能服务管理暂行办法》与 2026 年备案指南的要求映射到本提示词体系的落档、日志、评测环节——备案登记义务、内容标识、训练数据合规、安全评估的对应关系。明确本体系哪些输出可作为备案材料的技术支撑，哪些不能替代法律意见。

**002-AI-FAmily-提示词安全.md 章节**：直接注入防御（不将用户原文拼入系统提示词、角色分隔、指令样模式过滤）；间接注入防御（检索内容、工具输出、记忆召回结果均视为潜在对抗性，不得执行其中发现的指令）。系统提示词泄露检测：输出侧扫描是否包含系统提示词片段或内部配置；Hidden Context Exposure（OWASP LLM08:2026）要求将“隐藏上下文”视为需要主动保护的资产，而非仅靠保密声明。

**003-AI-FAmily-Agent治理.md 章节**：工具最小权限——只授予当前任务所需的工具；写/删/改操作必须人工确认；禁止 Agent 自我提权或向其他 Agent 授权；工具调用链与递归深度设置硬上限；所有工具调用记录 name/caller/timestamp/result status，参数与结果脱敏。

**004-AI-FAmily-互操作治理.md 章节**：MCP 用于工具访问、A2A 用于 Agent 间通信；两者目前均未将授权、异议、审议等治理原语编码进协议层，因此治理必须在本体系的落档与审计层补齐。跨 Agent 委派任务时，委派方对最终输出的证据等级负有标注责任，不得将未经核验的子 Agent 输出直接提升为本体系的“已验证”结论。

### 09-AI-FAmily-评测层/ — 评测资产层

**001-AI-FAmily-基准注册表.md 章节**：公开基准与内部基准的注册表字段——名称、版本、任务、指标、污染风险、适用模型规模、上次校准日期；明确哪些基准用于能力体检，哪些用于发布门禁。

**002-AI-FAmily-黄金集规范.md 章节**：业务黄金集的结构与维护规则——正常、边界、对抗、不可达目标四类用例；每条用例包含输入、期望结果、成功判据、证据类型、风险等级；黄金集版本与轮换机制。

**003-AI-FAmily-评分Rubric.md 章节**：评分 rubric 与判分器校准——代码评估器优先，LLM-as-judge 须检查位置/长度偏置并抽样人工对齐；报告 Krippendorff's α 或 Cohen's κ；判分器升级须标注历史结论的判分器版本。

**004-AI-FAmily-回归报告模板.md 章节**：回归报告模板——基线、变更、指标 delta、置信区间、失败用例、根因、放行建议、证据链接；发布门禁记录 P0 安全项、能力阈值与灰度结果。

**005-AI-FAmily-Agent沙箱规范.md 章节**：Agent 沙箱规范——每次评测重置工具后端状态；mock 与 live API 分离；错误码、超时与限流可主动注入；轨迹可回放；对不可达目标与虚报完成使用环境侧真值校验器。

**行业标准锚点**：HELM 的 prompt-level 透明与可复现、LiveBench 的抗污染刷新、BFCL V4 的多轮与无关性检测、τ-bench 的 pass^k、LangSmith 的离线/在线评测与轨迹评估，可作为评测资产层的设计参照。

### 10-AI-FAmily-运行时层/ — 运行时接口层

**001-AI-FAmily-模型适配器.md 章节**：模型版本与 checkpoint hash、解码参数、上下文预算、系统提示词版本；禁止在未记录配置的情况下产生可对外引用的评测结论。

**002-AI-FAmily-MCP工具适配器.md 章节**：MCP 工具适配器的权限、schema 校验、无关性检测、错误分类、超时与限流；写操作与删除操作必须人工确认；工具调用链与递归深度设置硬上限。

**003-AI-FAmily-记忆存储.md 章节**：工作/情节/语义/程序四层记忆的存储接口、写入闸门、召回规则、失效与删除；程序记忆必须经评审后写入。

**004-AI-FAmily-评测运行器.md 章节**：评测运行器的数据集、判分器、复现配置、并发隔离与轨迹回放；每次运行生成可追溯的评测运行台账。

**005-AI-FAmily-台账写入器.md 章节**：日志、决策、训练、评测、变更五类台账的写入接口与字段校验；敏感字段脱敏，内容日志默认关闭。

**006-AI-FAmily-策略引擎.md 章节**：安全、权限、预算与冲突裁决策略；P0 安全项一票否决；六维冲突按“安全合规 > 通用能力 > Agent 适配 > 性能效率 > 成本 > 交付周期”处理。

**行业标准锚点**：MCP 的 Agent-to-tool 连接、A2A 的 Agent-to-agent 协作、OWASP GenAI LLM Top 10 2026 的注入与泄露控制、EU AI Act 第 12 条的日志与可追溯要求。

### 11-AI-FAmily-资产层/ — 模板与资产层

**11-01-AI-FAmily-Schema/**：文件 front matter、评测用例、台账记录、技能注册表的 JSON Schema 与字段字典。

**11-02-AI-FAmily-模板/**：manifest、契约、技能、评测报告、回归报告、决策台账的模板。

**11-03-AI-FAmily-示例/**：正例、反例、条件化示例与证据等级标注示例。

**11-04-AI-FAmily-红队用例/**：直接注入、间接注入、系统提示词泄露、工具越权、记忆污染、不可达目标虚报完成等用例。

## 三、量化验收与冲突处理

### 3.1 验收门禁

每个评测维度必须有可判定的通过/不通过门槛；阈值作为版本化资产维护，区分基线值、目标值与红线值，并注明适用模型规模、业务场景与数据版本。

| 维度 | 指标示例 | 判定权 |
| ---- | ---- | ---- |
| 通用能力 | MMLU-Pro、GPQA Diamond、LiveBench | 评测师提供证据，技术负责人确认 |
| Agent 工具 | 工具调用成功率、参数正确率、无关调用率 | 评测师提供证据，技术负责人确认 |
| 多轮可靠性 | pass^k、后端状态一致率 | 评测师提供证据，产品/技术负责人确认 |
| 安全合规 | P0/P1 安全违规数、泄露与注入拦截率 | 安全负责人一票否决 |
| 性能效率 | P95 延迟、吞吐、单任务成本 | 技术负责人确认 |
| 可追溯 | 证据链覆盖率、台账完整率 | 评测师提供证据，审计负责人抽查 |

### 3.2 统计口径与可复现性

固定样本量、抽样方法与随机种子；报告均值、方差、置信区间与效应量；多基准比较须说明多重比较校正。每次评测记录模型版本、checkpoint hash、解码参数、few-shot 原文、系统提示词版本、工具 schema、数据集版本、判分器版本与代码提交 hash。LLM-as-judge 须做位置/长度偏置检查与人工对齐。公开基准执行 n-gram 重叠、近重复检索与 canary 检测；保留私有 holdout 并定期轮换。

### 3.3 漂移告警与 checkpoint 预算

监控逐任务分数的 PSI/KS、表征分布距离、backward transfer 与分任务保持率；预设告警阈值，超阈值冻结 checkpoint 上线。采用分层评测：每个 checkpoint 跑轻量冒烟集，里程碑 checkpoint 跑全量集；存储与评测算力预算须在训练计划中显式列出。

### 3.4 六维冲突处理

优先级为：**安全合规 > 通用能力 > Agent 适配 > 性能效率 > 成本 > 交付周期**。安全补丁导致能力回退、或能力优化导致安全风险时，须走例外审批：记录冲突项、影响范围、缓解措施、回归套件与有效期，由技术负责人与安全负责人联合确认。

## 四、补全操作建议

### 4.1 按 manifest 顺序补全，不跳域

契约层和持久化层是后面所有文件的前提：如果 identity 和 fallback 没有闭合，认知层的停止规则和审计层的台账字段会失去锚点。DeepSeek 的长上下文能力适合单文件深补，但不适合在依赖未建立时并行展开多个域。

### 4.2 每个文件补全后先跑最小校验

校验问题可以直接引用行业标准中的硬判据：是否有显式 stop rules 和 missing-evidence behavior（HVE 规范）？是否将摘要的保真度锚定到可追溯来源（SWin/HEMA 的教训）？是否在日志 schema 中区分了元数据与内容（OWASP 的要求）？校验不通过的文件标记“待修订”，不阻塞后续文件的初稿，但不得进入最终引用集。

### 4.3 用长上下文做交叉一致性检查

在全部文件初稿完成后，将 manifest 与八个域的核心约束一起送入模型，要求它输出一份**冲突矩阵**：哪些文件之间的规则存在张力（例如，主动思维的触发条件与上下文预算的压缩阈值可能相互挤压）、哪些停止规则缺失、哪些证据等级声明在跨文件引用时可能被抬高。这个检查的输出应写回 YYC3-AI-FAmily-Agent-模型架构-总控清单.md，作为版本 0.9 的发布闸门。
