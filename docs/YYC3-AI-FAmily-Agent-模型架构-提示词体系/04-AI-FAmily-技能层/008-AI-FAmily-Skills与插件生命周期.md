## 一、目的

让 Skills 与插件从“临时脚本”变成“可治理资产”：每个阶段有明确输入、输出、责任人、门禁与证据。

## 二、生命周期阶段

| 阶段 | 目标 | 关键产出 | 门禁 |
| ---- | ---- | ---- | ---- |
| 提案 | 说明问题、边界与收益 | 提案单、适用范围、非目标 | 场景真实、非重复建设 |
| 设计 | 定义接口、权限、失败模式 | 设计说明、schema、权限矩阵 | 权限最小化、可回退 |
| 安全评审 | 识别数据、注入、越权风险 | 威胁模型、缓解措施 | 高风险项有闭环 |
| 实现 | 完成代码/提示词/配置 | 版本、测试、示例 | 代码/提示词通过评审 |
| 评测 | 验证正确性、可靠性、安全性 | 评测报告、黄金集结果 | 达到预注册阈值 |
| 注册 | 进入注册表与运行时 | manifest、owner、eval_suite | 字段完整、状态 active |
| 监控 | 观察质量、成本、延迟、告警 | 运行台账、告警记录 | 超阈值触发复核 |
| 弃用 | 安全退出或替换 | 弃用通知、替代方案、保留期 | 无未迁移调用方 |

## 三、角色与责任

| 角色 | 责任 |
| ---- | ---- |
| 提案人 | 说明问题、范围、收益与风险 |
| 技能/插件 owner | 设计、实现、维护、响应告警 |
| 安全评审 | 数据边界、权限、注入与越权评审 |
| 评测负责人 | 设计评测用例、出具证据与置信度 |
| 运行时负责人 | 接入、监控、灰度与回滚 |
| 技术负责人 | 放行、例外审批与资源协调 |

## 四、门禁与证据

- 自研类型：设计评审、评测通过、版本与回退方案。
- 调用类型：供应商尽调、数据协议、限额与停服预案。
- 混合类型：自研 + 调用的全部要求，另加内部权限、审计与降级。
- 写操作/删除操作：人工确认闸门与操作审计。
- 程序记忆写入：评审闸门与来源标注。

## 五、弃用与替换

- 提前通知调用方，给出替代方案与迁移窗口。
- 保留旧版本回退窗口；到期后从注册表标记 `retired`。
- 弃用决策写入决策台账，记录影响范围、替代方案与有效期。
